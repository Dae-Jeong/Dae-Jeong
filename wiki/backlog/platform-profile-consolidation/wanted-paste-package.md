# 원티드 붙여넣기 패키지 — v6 (관점 선언) 기준

**이력서 주소**: https://www.wanted.co.kr/cv/fF1dU0gKAAsDCw4BRE4=

클릭으로 되는 것(재직 형태·졸업·스킬 9건·중복 삭제)은 이미 반영돼 있다.
**각 필드: 복사 → 붙여넣기 → 다른 곳 클릭(blur) → 새로고침으로 저장 확인.**

## 1. 간단 소개

```
LLM 기능을 제품에 붙이는 일보다, AI의 출력을 판정하고 통제해서 사람이 믿고 쓸 수 있는 제품으로 만드는 일에 관심이 있습니다.

그래서 LLM 백엔드, Agent Workflow, Evaluation을 중심으로 문제 정의부터 설계, 구현, 평가, 운영까지 제품의 전체 과정을 다룹니다.

"품질이 나쁘다"는 말로는 뭘 고쳐야 할지 알 수 없습니다. AI가 만든 결과물의 품질을 자동 게이트, 실측 분포 대조, 사람 판정 세 층으로 나눠 판정할 수 있게 만들었습니다.

제가 계속 붙들고 있는 질문은 하나입니다. "AI가 구현을 점점 더 많이 맡을수록, 사람이 끝까지 책임져야 하는 층을 어떻게 지킬 것인가?"

사람들에게 필요한 AI 제품을 4년째 만들어온 엔지니어로서, 이 질문의 답을 의료 AI 플랫폼에서 제품으로 만들어가고 있습니다.
```

```

```

## 4. 메디솔브에이아이 주식회사

| 필드 | 값 |
| --- | --- |
| 직무 | `백엔드 개발자` |
| 직책 | `기업부설연구소장` |
| 주요 성과(제목) | `AI 제품 backend 구축·운영과 LLM 평가·Agent Workflow 설계` |

설명 (원티드용 bullet 하이브리드 — 문제/판단/실행/성과 구조, 원티드 AI 리뷰 반영):

```
[Thready — AI 콘텐츠 생성 제품 backend 전면 재구축]
- 문제: 도메인 간 의존성 — 회원 로직 수정이 AI 생성 중단으로 전파되고, QA 티켓을 닫아도 같은 영역에서 재발 반복
- 판단: 부분 수정으로는 의존성 구조가 남는다고 보고, "돌아가는 기능을 왜 다시 만드나"라는 반대를 문제 누적·AI 모듈 확장 계획·하네스 기반 이관 속도로 설득
- 실행: 디자인 패턴과 인프라 하네스를 먼저 세운 뒤 AI 코딩 에이전트와 협업 — 파악부터 재구축까지 작업 시간 기준 36시간
- 성과: QA 티켓 reopen 비율 37% → 11% (cutover 전후 Jira 집계) · 월 수만 건 규모 HTTP 5xx 0.3% 수준 운영 (30일 기준)

[LLM Evaluation — 생성 품질을 판정 가능한 대상으로]
- 문제: "품질이 나쁘다"로는 재생성 기준을 정할 수 없음
- 해결: 자동 게이트 12종 · 직접 수집한 실측 코퍼스(n=19→4,039)와의 분포 대조 · 사람 판정 — 세 층의 평가 체계 구축
- 운영: 반증된 프롬프트 규칙을 기록으로 남겨 같은 시도의 반복을 차단

[Agent Workflow — planner·writer 파이프라인 설계·구현]
- 평가 하네스와 함께, 하네스로 검증할 agent 구조 자체를 설계·구현 (대표 영역: writer)
- 유형 분기 판정을 writer에 뒀을 때 18건 전부 미발동 — writer는 원본 유형을 알 수 없는 자리였기 때문
- 판정을 planner로 옮겨 해결 — 판단을 어느 역할에 둘 것인가가 agent 설계의 핵심임을 실측으로 확인

[Centurion — 피부과 운영 CRM backend]
- order·product·inventory API와 비동기 worker 흐름 구축 — 직전 회사에서 결제 실패의 불일치를 수습한 경험을 바탕으로, 실패 가능한 작업을 제품 시작 시점부터 API 경계 밖 worker로 분리하고 재고 차감에 retry 적용
- 메시지 계층 Celery → TaskIQ 전환, 알림 도메인 분리
- 상담 현장을 실시간으로 돕는 AI 에이전트(WebSocket 기반 STT·LLM 파이프라인)를 공동 주 기여로 구축 중

[조직 표준·AX — 사람과 에이전트가 같은 규칙 위에서]
- 조직 표준 FastAPI 템플릿 설계·구축 — layered architecture, 의존성 주입, 응답·예외 규약, ADR·runbook
- 계층형 agent context와 도메인·셋업 자동화 스킬 내장 — AI 코딩 에이전트 협업 워크플로우를 팀에 도입
- 신규 backend가 같은 구조에서 출발하므로 제품 정책만 파악하면 누구든 대응 가능

Backend Engineer로 위 시스템을 담당하며 기업부설연구소장·Tech Lead·PO를 병행하고 있습니다.
```

인턴으로 1개월간 병원 내부 일정 관리 어드민을 0에서 구축한 뒤 정규직으로 전환했고, 회사 폐업으로 재직이 종료됐습니다.

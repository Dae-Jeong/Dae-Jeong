# 원티드 붙여넣기 패키지

**이력서 주소**: https://www.wanted.co.kr/cv/fF1dU0gKAAsDCw4BRE4=

원티드는 텍스트 필드에 자동 입력이 저장되지 않아 ([자동화 제약 실측](sync-spec.md)) 사람 손이 필요하다.
클릭으로 되는 것(재직 형태·졸업·스킬 9건·중복 삭제·AX)은 이미 반영돼 있다.
**아래 8개만 복사→붙여넣기→다른 곳 클릭(blur)→새로고침으로 저장 확인**하면 끝난다.

---

## 1. 간단 소개

```
AI 제품을 만드는 일만 4년째 하고 있습니다. 모델을 만들다 기획으로, 다시 백엔드로 자리를 옮겼고 지금은 만드는 일과 무엇을 왜 만들지 정하는 일을 함께 맡고 있습니다.

백엔드를 택한 건 AI가 구현을 점점 더 많이 맡게 될수록, 보안과 안정성처럼 사람이 끝까지 책임지는 층의 무게가 커진다고 봤기 때문입니다. 지금 AI와 협업해 제품을 만들면서 그 생각은 더 확고해졌습니다.

"품질이 나쁘다"로는 고칠 대상을 정할 수 없습니다. AI 생성 품질을 자동 게이트와 실측 분포 대조, 사람 판정 3층으로 나눠 판정 가능하게 만들었습니다.
```

## 3. 메디솔브에이아이 주식회사

| 필드 | 값 |
| --- | --- |
| 직무 | `백엔드 개발자` |
| 직책 | `기업부설연구소장` |
| 주요 성과(제목) | `AI 제품 backend 구축·운영과 제품팀 리드` |

설명:

```
[Thready] 속도를 우선해 빠르게 검증된 초기 제품의 backend를 인계받아 FastAPI로 재구축했습니다. 회원 로직을 수정하면 AI 생성이 중단되는 식으로 변경이 전파되는 도메인 의존성이 문제였고, "돌아가는 기능을 왜 다시 만드나"라는 반대를 문제 누적·AI 모듈 확장 계획·하네스 기반 이관 속도로 설득했습니다. FE(Next.js)는 유지하고 backend만 교체했으며, 파악부터 재구축까지 작업 시간 기준 36시간이 걸렸습니다. cutover 전후 Jira 집계에서 QA 티켓의 resolve 대비 reopen 비율은 37%에서 11%로 감소했고, 현재 30일 기준 월 수만 건 규모에서 HTTP 5xx 0.3% 수준으로 운영하고 있습니다.

[Centurion] 피부과 운영 CRM의 order·product·inventory API와 비동기 worker 흐름을 구축했습니다. 직전 회사에서 결제 실패의 불일치를 직접 수습한 경험을 바탕으로, 주문·결제처럼 실패 가능한 작업을 제품 시작 시점부터 API 경계 밖 worker로 분리하고 재고 차감에는 retry를 붙였습니다. 이후 Celery에서 TaskIQ로 메시지 계층을 전환하며 알림 도메인을 분리했습니다.

[조직 표준] 조직 표준 FastAPI 템플릿을 설계·구축했습니다. layered architecture, 의존성 주입, 응답·예외 규약, ADR과 runbook을 담고 계층형 agent context를 내장해, 소수 백엔드 인원이 다수 제품을 담당하는 구조에서 제품 간 이동 비용을 낮췄습니다.

Backend Engineer로 위 시스템을 담당하면서 기업부설연구소장과 Tech Lead, PO를 병행하고 있습니다.
```

## 0. 두 개의 축을 먼저 정리한다

이번 개정에는 **성격이 다른 두 원칙**이 섞여 있다. 헷갈리면 잘못 적용된다.

| 원칙 | 무엇을 정하나 | 적용 범위 |
| --- | --- | --- |
| **Dual track** | 나를 뭐라고 부르나 | **전 산출물** — 이력서·플랫폼 가리지 않음 |
| **정량의 위치** | 수치를 어디에 두나 | **소개 필드에서 빼고 경력 상세로** |

두 번째가 특히 오해되기 쉽다. user-confirmed 원문은 **"정량적 이야기는 내부로 들어와서 보면 돼"**다.

### "내부"가 어디인가 — 경계선

```
   외부(후킹)                          내부(검증)
┌─────────────────────┐      ┌──────────────────────────┐
│ 플랫폼 소개·자기소개   │  →   │ 웹 이력서 · 포트폴리오      │
│ 링크드인 About        │      │ 각 플랫폼 경력 상세         │
│ 헤드라인              │      │ claim registry            │
├─────────────────────┤      ├──────────────────────────┤
│ 정성 서사             │      │ 수치 · 근거 · claim ID     │
│ "왜 이 사람인가"       │      │ "정말 그런가"              │
└─────────────────────┘      └──────────────────────────┘
```

⚠️ **웹 이력서는 "내부"다.** 수치를 빼지 않는다. 오히려 여기가 수치의 집이다.
소개글을 읽고 넘어온 사람이 확인하러 오는 곳이기 때문이다.

## 1. Dual track 표현 — 3단 변형

같은 뜻을 길이에 맞춰 세 가지로 쓴다. **의미가 흔들리면 안 되므로 변형을 고정한다.**

| 길이 | 문구 | 쓰는 곳 |
| --- | --- | --- |
| **최소** | `Backend Engineer · PO` | 직함 필드, 헤드라인 앞머리 |
| **한 줄** | `AI 제품을 만들고, 무엇을 왜 만들지도 정하는 백엔드 엔지니어` | 캐노니컬 원라인, 이력서 최상단 |
| **착지 문장** | `무엇을 왜 만들지 정하는 일과 그것을 직접 만드는 일을 함께 하고 있고, 그 둘이 붙어 있을 때 제품이 가장 빨리 좋아진다고 믿습니다` | 소개 마지막 문장 |

**착지 문장이 핵심이다.** "둘 다 한다"로 끝나면 병기가 초점 분산으로 읽힌다.
**"둘이 붙어 있어서 빠르다"**로 착지해야 희소성이 된다.

## 3. 리멤버 — 소개 (재작성 대상)

### 문제

현재 들어가 있는 1,279자 3축 전문은 **이번 원칙 이전에 넣은 것**이다.

- 수치가 소개에 있다 (`37%→11%`, `HTTP 5xx 0.3%`, `일평균 94% 감소`)
- dual track이 없다
- 헤드헌터가 스크롤하며 보는 화면에 1,279자는 길다

### 초안

```
Vision AI 엔지니어로 시작해 PM을 거쳐 백엔드로 왔습니다. 돌아온 게 아니라, 제품을 끝까지 책임지는 자리를 고른 쪽에 가깝습니다.

인계받은 제품을 볼 때 버그부터 세지 않고 문제 정의가 맞는지부터 봅니다. 한번은 품질 기준값이 실측이라고 믿고 있었는데, 다시 재보니 우리 출력을 우리가 되먹이고 있었습니다. 스스로 만든 순환이었고, 기준을 다시 세우면서 문제 정의 자체가 틀렸다는 것도 함께 드러났습니다.

"좋다/나쁘다"로 말하면 무엇을 고쳐야 할지 알 수 없다고 생각합니다. 판정할 수 있게 만들고, 한 번 푼 문제는 팀이 반복해 쓸 수 있는 형태로 남깁니다.

지금은 무엇을 왜 만들지 정하는 일과 그것을 직접 만드는 일을 함께 하고 있습니다. 그 둘이 붙어 있을 때 제품이 가장 빨리 좋아진다고 믿습니다. 구체적인 성과 수치와 프로젝트 상세는 경력 항목에 정리해 두었습니다.
```

**리멤버는 문단 구분이 들어간다** (링크드인과 달리 일반 textarea라 native setter로 개행 입력이 가능하다). 4문단으로 나눴다.

마지막 문장(`구체적인 성과 수치와…`)은 **소개 → 경력 상세로 유도하는 다리**다. 수치를 뺀 자리에 "없는 게 아니라 아래 있다"를 명시한다.

⚠️ 리멤버는 **커넥트용·채용 서비스용 두 탭**이 있고 현재 같은 내용이다. 둘 다 교체한다.

## 검토 포인트

확정 전에 판단이 필요한 것들이다.

1. **"4년차"를 dual track 문장에 붙일지** — 초안은 웹 이력서에만 붙였다. 플랫폼 소개에는 연차 필드가 따로 있어 중복이다
2. **실패담(되먹임)을 전 플랫폼에 반복할지** — 강한 소재지만 5곳에 같은 이야기가 깔린다. 링크드인·리멤버에만 두고 나머지는 뺄 수도 있다
3. **"구체적인 성과 수치는 경력 항목에" 유도 문장** — 친절하지만 군더더기로 읽힐 수도 있다

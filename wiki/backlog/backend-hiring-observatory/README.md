# Backend Hiring Observatory

## 한 줄

검토한 채용공고를 LLM이 읽고 연결할 수 있는 위키로 축적해, 관측한 BE 채용 요구와 나의 지원·학습 우선순위를 함께 파악한다.

## 메모

- 사용자 제안: 개별 공고 검토를 일회성으로 끝내지 않고 BE 채용 트렌드 분석에 활용한다. 2026-09-07 공고 분석 스킬에 키워드 적재·집계를 포함하도록 승인했다. 정기 수집·시계열 확장은 미착수다.
- 기존 JD product의 feature map·gap map을 확장하는 후보다. 별도 원장이나 크롤러를 먼저 만들지 않는다.
- 최소 단위 후보: 공고 URL/ID, 회사·직무, 요구 연차, 도메인, 필수/우대 구분, 기술, 기대하는 업무 결과, 확인일과 게시일(미상이면 미상), 원문 근거 위치. 공고 재게시·중복은 구분한다.
- LLM은 표현 정규화와 관계 연결·해석을 맡고, 빈도와 분모는 구조화된 기록에서 계산한다. 근거 없는 추론은 원문 사실과 분리한다.
- 위키는 공고별 기록과 역량별 연결을 제공하고, 시점별 보고서는 관측 범위·표본 수·근거를 명시한다. 개인 강점/공백은 기존 profile/evidence를 참조한다.
- 개인에게 추천되거나 직접 고른 공고는 선택 편향이 있으므로 우선 ‘관심 공고에서 관측한 요구’로 표현한다. 전체 BE 시장의 대표 표본으로 취급하지 않는다.
- 한 시점의 빈도와 시간에 따른 증감은 다르다. ‘증가했다’는 판단은 비교 가능한 수집 범위·기간·분류 기준이 확보된 뒤에만 한다. AI 직군과 일반 BE, 연차·회사 특성도 섞어 집계하지 않는다.
- 초기 확인 질문: 반복되는 핵심 책임은 무엇인가, AI 역량은 필수인가 우대인가, 내 검증된 강점이 통하는 역할은 무엇인가. 기술 키워드 인기만으로 학습 우선순위를 정하지 않는다.
- 가장 작은 실험 후보: 저장을 승인한 공고부터 동일한 형식으로 축적하고 짧은 관측 노트가 실제 지원 판단에 도움이 되는지 본다. 전용 검색/그래프 DB·대시보드·새 스킬은 필요 확인 후 결정한다.
- 정규화 관측의 기본 적재는 승인됐으며 상세 경계는 아래 product contract가 소유한다. 원문 전체·정기 수집은 승인 범위 밖이다.

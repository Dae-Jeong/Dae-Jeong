# Recency Weighting Policy

**최근 일이 지금의 나를 더 정확히 설명한다.** 오래된 성과가 최신 실적보다 넓은 지면을 차지하면, 독자는 "지금 무엇을 하는 사람인가"를 읽지 못한다.

이 규칙은 resume, portfolio, 채용 플랫폼 프로필에 공통 적용한다.

## 핵심 원칙 — 분량과 검증 자산을 분리한다

시간 가중을 단순 적용하면 문제가 생긴다. STUDIO LAB(2021.12–2024.01)은 오래됐지만 **CES 2024 수상과 특허**를 갖고 있다. 시간 순으로 눌러버리면 가장 강한 제3자 검증이 사라진다.

그래서 두 축을 나눈다.

| 축 | 기준 | 적용 |
| --- | --- | --- |
| **서술 분량** | 최근일수록 넓게 | 경력 bullet 수, portfolio case 깊이 |
| **검증 자산** | 시점 무관 | Credentials 섹션에서 독립 노출 |

CES·특허·외부 인증은 **경력 서술 안에 묻지 않고 Credentials로 올려** 시점과 무관하게 보이게 한다. 경력 섹션에서는 해당 시기를 짧게 유지한다.

## 분량 배분 기준

현재 시점(2026-08) 기준 권장 비중이다. 절대값이 아니라 상대 비율이며, JD tailoring에서 조정할 수 있다.

**2026-08-12 갱신**: 경력 설명이 역량 축 구조([career-axes](../products/resume/career-axes.md))로
바뀌면서 단위를 축·bullet로 재정의했다. 분량이 넘칠 때 **현재 회사를 자르지 않고 과거를 압축한다**
(user-confirmed: "다른 회사쪽을 좀 compact하게 해줘도 되잖아").

| 시기 | 대상 | 축 | bullet | portfolio case |
| --- | --- | --- | --- | --- |
| 현재 (2025.04~) | MediSolve AI | **최대 6** | **가장 넓게** — 25~30 | 상세 case 2~3건 |
| 직전 (2024.10~2025.04) | 더데이랩스, Memento AI | 각 1 | 각 2~3 | 필요 시 1건 |
| 과거 (2021.12~2024.01) | STUDIO LAB | 3 | 6 (검증 자산 우선) | 1건 |
| 초기 (2020.08~2021.06) | 아이즈솔 | 1 | **2 이하** | 없음 |

목표 비율 — **현재 회사 : 나머지 전부 ≈ 2 : 1**.
국내 인사담당자 증언상 3장을 넘기면 읽기를 포기하므로, 총량은 늘리지 않고 배분만 바꾼다.

원칙:

- 현재 소속의 서술이 **전체 경력 서술의 절반 이상**을 차지한다.
- 초기 경력은 **궤적을 잇는 최소 문장**만 남긴다. 상세 성과는 쓰지 않는다.

## 과거 정량은 쓰지 않는다 (2026-08-08 확정)

**오래된 프로젝트의 정량 수치는 검증 여부와 무관하게 공개 산출물에 쓰지 않는다.**

검증만 하면 쓸 수 있다고 보기 쉬우나, 그렇지 않다. 3년 전 모델 정확도나 처리 시간은 **현재 포지셔닝을 설명하지 못하면서 최신 실적과 같은 지면을 놓고 경쟁한다.** 결과적으로 무게중심을 흐린다.

| 대상 | 미사용 | 대체 표현 |
| --- | --- | --- |
| 초기 인턴기 모델 지표 | 정확도·처리량 수치 | "안면 인식 기반 자동 출결 시스템 개발" |
| 과거 AI 모델 성능 | 정확도 %, 학습 지표 | "Vision AI 기반 이미지 분석 모델 개발" |
| 과거 제품 개선 수치 | 처리 시간 단축률, 상한 개선치 | "자동 생성 파이프라인 구축" |
| 개인 프로젝트 코드 규모 | 패키지·엔티티·엔드포인트 개수 | **협업 규모** — "10명 팀의 백엔드 2명 중 주도" |

원칙: **과거는 "무엇을 했는가"까지, 현재는 "무엇이 바뀌었는가"까지.** 정량은 현재 실적의 몫이다.

예외는 제3자 검증뿐이다 — 외부 기관 인증·수상은 **수치를 빼고 사실만** 남겨 Credentials에 배치한다. "정확도 99% 인증"이 아니라 "AI 정확도 부문 인증 통과".

## 예외 — 시점을 이겨도 되는 것

아래는 오래돼도 분량을 유지한다.

1. **제3자 검증** — 외부 기관 수상·인증·특허. 단 Credentials 섹션에 배치하고 경력 본문에서는 한 줄로 참조한다.
2. **궤적 서사의 전환점** — `AI Engineer → PM → Backend Engineer` 전환처럼 현재 포지셔닝을 설명하는 데 필요한 대목. 다만 "무엇을 했는가"가 아니라 "왜 옮겼는가"만 남긴다.
3. **현재 작업의 원류** — 과거 작업이 현재 것의 명백한 선행 사례일 때. 예: STUDIO LAB의 Nest.js 개발 템플릿 제작(2023.08~12)은 현 조직 표준 template 설계의 첫 사례다. 이 경우 과거를 단독 서술하지 않고 **현재 항목에 계보로 붙인다**.

## 안티패턴

- ❌ 초기 경력의 정량 수치를 최신 실적과 나란히 배치 — 예: 아이즈솔 인턴 시기 모델 정확도를 현재 운영 지표와 같은 줄에 두는 것
- ❌ 오래된 프로젝트를 "가장 자랑스러워서" 상단에 두기 — 자랑스러움과 현재 설명력은 다르다
- ❌ 학부 프로젝트를 실무 프로젝트와 같은 섹션에 나열
- ❌ 시간 가중을 이유로 CES·특허를 경력 서술 안에 묻어 눈에 안 띄게 만들기

## 플랫폼 적용

플랫폼마다 섹션 구조가 달라 분량 통제 수단이 다르다.

| 플랫폼 | 통제 수단 |
| --- | --- |
| 리멤버·그룹바이 | 경력별 상세 서술 길이 |
| 사람인 | 경력기술서 항목 수 |
| 링크드인 | 경력별 description 길이 |
| 원티드 | 경력 설명 유무 |
| 로켓펀치 | 프로젝트 섹션 구성 — **현재 학부 프로젝트 5건만 등록돼 있어 규칙 위반 상태** |

## 재검토 주기

현재 소속 기간이 길어지면 비중이 자연히 커진다. **소속이 바뀌거나 주요 프로젝트가 종료될 때** 이 표를 다시 조정한다. 마지막 조정: 2026-08-08.

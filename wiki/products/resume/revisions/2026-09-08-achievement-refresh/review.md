# 검토 기록

**내용 검토 통과 — 남은 필수 수정 없음.** 사용자 승인이나 공개 반영 완료를 뜻하지 않는다. 4종 문서는 `content-review / approved:false`를 유지한다.

## 검토 방식

기존 코드 조사에 참여한 검토 에이전트가 현재 공개 문안의 독립 관찰을 먼저 작성한 뒤, 별도 작성자와 조정자가 만든 4종을 교차 검토했다. 작성 에이전트도 조정자가 작성한 포트폴리오·CV를 대조했다. 조사 맥락을 공유했으므로 blind review나 서로 다른 모델 간 대결로 표기하지 않는다.

검토 범위는 공용 문안, 해당 profile/evidence/claim, 내용 계약·표현 규칙이다. 회사별 제출본·frozen 패키지와 플랫폼은 수정하지 않았다.

## 반영한 지적

| 항목 | 수정 |
| --- | --- |
| 고객 문제와 성과 위계 | 기존 채널 운영자의 시간·경험 부족과 Threads 진입 장벽을 먼저 설명. 고객 한 사례의 성장과 2026.08 팀 매출은 최근 기능 문단 앞의 별도 제품 결과로 배치 |
| 주문·알림 복구 | 확인되지 않은 자동 재시도 종결·주문 commit 후 알림·핵심 업무 반드시 완료 표현 제외. 실제 상태·실패 기록·수동 재발송은 유지 |
| 공유 인증 | SSO 전체 구축이 아닌 Redis 세션 v2의 주도권으로 한정. 이전 구조가 사용자 하나만으로 세션을 구분했다는 미확인 가정 제거 |
| 지식 검색 | 삭제된 생성·shadow 모듈을 현재 운영 구조로 표현하지 않음. 현재 검색·검수·공개 경계와 임상 검수 준비를 분리 |
| 트랜잭션 전파 | 포트폴리오에서 REQUIRES_NEW의 별도 커밋과 NESTED의 기존 트랜잭션 내부 SAVEPOINT를 별도 행으로 분리 |
| 결제 상태 | 경력기술서의 `승인 대기`를 `매입 대기`로 정정해 requires_capture 의미와 일치 |
| CV의 모델 개발 | 미확인 각도·태그·스타일 분류를 제거하고 `의류 이미지 분석 모델 개발 참여`로 한정 |
| CV의 범위 | 핵심 화면의 coding agent 활용, 현재 지식 검색 책임, 재직·직무 구간·외부 활동을 보완. 임상 검수 준비는 일상적인 표현으로 정리 |
| 공개 본문의 검토 메타 | `코드와 테스트 소스로 확인`, `앞의 결과와 별도` 같은 조사자 문장을 포트폴리오에서 제거. 실제 구현·기록된 로컬 검증을 설명하고 인과 경계는 이 패키지 README·evidence에 유지 |

## 유지한 강점과 편집 판단

- 이력서의 대표 성과→경력 구조를 유지했다. 포트폴리오는 같은 3축과 순서로 깊이를 확장한다.
- 제품·백엔드·AI·핵심 화면의 직접 구현, 실패 처리, 세션 수명, 팀 적용 결과를 살렸다. QA 하네스는 제품의 재구축·검증을 뒷받침한다.
- 경력기술서는 대표 사례뿐 아니라 주문·재고·인증·상담·운영/예약·검색·결제·이전 PM까지 책임 범위를 넓혔다. CV는 그 설득 문장을 반복하기보다 시간축과 활동·검증 자산을 정리했다.
- 이력서 첫 성과의 여섯 문단은 조판 시 `제품·고객 결과 / 생성·승인·발행 / AI 실행·원장`의 세 묶음으로 스캔하기 쉽게 만들 수 있다. 현재는 사용자가 만족한 글 구조와 자립적인 기술 설명을 유지하고, 실제 화면에서 밀도를 확인할 선택 개선으로 남긴다.

## 검증

| 검사 | 결과와 범위 |
| --- | --- |
| `uv sync --project tools` | PASS. 기존 도구 의존성 동기화, dependency/runtime 선언 변경 없음 |
| `make verify` | PASS · wiki scope · metadata/path/link/claim 및 workspace 검사. 기록 `output/harness/runs/20260908T003454.json` |
| `make verify ARGS=--scope=copy` | PASS · workspace validator + TypeScript 검사 + 기존 로컬 활성 route 13개 HTTP 200. 기록 `output/harness/runs/20260908T003649.json` |
| 새 Markdown 별도 대조 | PASS · 네 문서의 섹션별 주석과 claim-map 집합 일치. 고유 public claim 76개: 이력서 59 / 경력기술서 73 / 포트폴리오 29 / CV 50 |
| 새 Markdown 공개 표현 | PASS · 기존 copy-gates의 금지 패턴, 절대경로 노출, 고정 브랜드 문장 1회, 승인 상태·canonical source 경로 검사 |
| `git diff --check` | PASS |
| 문안 교차 검토 | PASS · 최종 필수 지적 해소. 수치·동사·버전·환경·실행 여부와 문서별 역할 확인 |

로컬 route 검사는 **기존 화면의 회귀 확인**이며 새 Markdown이 그 화면에 반영됐다는 뜻이 아니다. 로컬 확인용 서버를 잠시 실행했으며 공개 배포는 하지 않았다. 공개 `/resume`·`/portfolio`는 HTTP 200, `/career/common`·`/cv/common`는 HTTP 404를 확인했다. 후자는 현재 manifest의 local 문서와 공개 접근 제한 상태이므로 이번 개편에서 공개로 전환하지 않았다.

원본 제품의 테스트·DB·외부 API를 이번에 재실행하지 않았다. 코드·테스트 소스와 과거 릴리스 검증 기록을 읽은 것이며, 이 문서의 새 workspace 검증과 구별한다. 새 HTML·PDF·시각화·PC 조판 검증은 내용 승인 후 진행할 단계로 남겼다.

## 다음 반영 경계

사용자가 문안을 확인한 뒤 공용 웹 4종·포트폴리오 상세 본문을 함께 반영하고 실제 렌더를 검수한다. 기존 공개본에서 확인한 구문·QA 위계·BAY 보장 등의 baseline 이슈는 이 초안에서 해소했지만 공개본에는 아직 남아 있다. 회사별·제출 완료 문서나 플랫폼까지 자동 전파하지 않는다.

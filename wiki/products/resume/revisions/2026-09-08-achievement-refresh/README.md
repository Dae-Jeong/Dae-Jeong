# 공용 4종 성과 개편안

사용자가 수용한 문안을 **공용 웹 4종에 로컬 반영한 검토 기록**이다. 이 폴더의 Markdown·claim map은 당시 내용 검토 스냅샷이며, 현재 표현 수정은 `app/fe/content/common/`에서 수행한다. 사실·기여 강도는 [evidence](../../../../evidence/README.md), 경력·학력은 [profile](../../../../profile/README.md)가 계속 소유한다. `approved: false`는 최종 조판·제출 승인을 받았다는 뜻으로 확대하지 않기 위해 유지한다.

## 공용 웹 4종 반영

- 검토 허브 `/common` → 이력서 `/resume`, 경력기술서 `/career`, 포트폴리오 `/portfolio`, CV `/cv`. 허브·문서 간 검토 nav는 개발 환경에서만 제공한다.
- 이력서는 고전 양식을 우선 적용하되 아래 기존안 비교를 유지한다. 이는 사용자의 최종 양식 선택을 대신하지 않는다.
- 문단·표·claim을 재요약 없이 app JSON으로 옮겼다. 포트폴리오는 세 축의 본문, 생성·승인 처리 단계, 발행 복구 상태표, 원장→전달 워커→AI 수신 경계를 포함한다.
- 회사별 패키지가 `content/documents/common.ts`를 직접 참조하므로 해당 기반은 보존했다. 현재 공용 route만 새 표현을 소비하며 `/career/common`·`/cv/common`은 root 공용 경로로 연결한다.
- `tools/export_common_review.mjs`는 이 스냅샷의 최초 승격 patch를 출력하는 명시적 adapter다. 사이트 런타임은 wiki를 읽지 않으며 이후 app 문안을 자동 덮어쓰지 않는다.
- HTML 본문·claim 대조와 PC·모바일 렌더 검사는 `app/fe/app/common/browser-check.mjs`, 결과·PNG는 `output/harness/common-refresh/`에 남긴다. PDF·EN·플랫폼 동기화·배포는 이번 변경에 포함하지 않는다.
- 검증 완료: 공용 4종 × PC 1440×900·1920×1080·모바일 390×844의 12개 상태에서 문안 누락·claim 불일치·중복 anchor·본문 가로 넘침 0건. résumé 59·career 73·portfolio 29·CV 50개 claim을 대조했고 PC/모바일 대표 PNG를 직접 검수했다. 기존 UI 비교의 9개 상태도 재검사했다.
- import adapter 단위 검사 3건, scoped ESLint·TypeScript·production build·`make verify` PASS. active route 13개 200, production의 `/common`·`/resume/compare` 404를 확인했다. 회사별 content·기존 shared documents·case library는 diff가 없다. 최종 검증 기록은 `output/harness/runs/20260908T110308.json`이다.

## 유지한 것과 바꾼 것

- 고정 브랜드·공용 역할, 이력서의 소개→대표 성과→경력→기술 흐름을 유지했다. 문서별 역할은 [패키지 계약](../../document-package-contract.md)을 따른다.
- 첫 성과의 출발점을 일반적인 콘텐츠 제작이나 매출 규모에서 **기존 채널 운영자의 시간·경험 부족과 Threads 진입 장벽**으로 바꿨다. 소재 활용·생성·고객 승인·발행을 연결한 제품 구현으로 답한다.
- 최근 코드에서 확인한 생성·승인·발행 복구를 기존 운영 성과와 구별했다. 고객 한 사례의 10배 이상 팔로워 성장과 2026.08 팀 제품의 구독 매출은 보조 결과다.
- SSO는 인증 시스템 전체가 아니라 Redis 세션 v2 영역의 주도권을 보강했다. 주문·알림은 실제 상태·실패 기록·수동 재발송을 설명하고 확인되지 않은 자동 재시도 보장은 뺐다.
- 백엔드 템플릿은 직접 설계·구축과 팀 사용 결과를 살렸다. QA 하네스는 제품의 재구축·검증을 뒷받침하는 기여로 배치했다.
- 경력기술서는 대표 3축 밖에도 예약·운영 관리·지식 검색·결제·이전 PM의 책임을 남겼다. CV는 직무별 기간·별도 법인의 프리랜서 이력·외부 활동을 보완했다.

## 팀 작업과 검토

- 근거 정리: 기존 코드 조사 에이전트가 source 버전·작성 기여를 대조하고 evidence·claim을 적재했다.
- 작성: 별도 작성 에이전트가 이력서·경력기술서를, 조정자가 포트폴리오·CV와 claim 연결을 작성했다.
- 검토: 기존 조사에 참여한 별도 검토자가 기존 공개본의 독립 관찰을 먼저 제출한 뒤 4종을 교차 검토했다. 필수 지적은 반영했고 내용 검토를 통과했다. 조사 맥락을 공유한 검토이며 blind review로 표기하지 않는다.
- 검토·검증의 최종 결과는 [검토 기록](review.md)에 남겼다. 소스 코드·테스트 파일 확인과 테스트 실행, 실제 고객 운영은 별개로 구분한다.

## 후속 시각화 구성

최초에는 이력서 UI 비교만 요청받아 아래 화면을 구성했다. 후속으로 공용 4종 구성을 요청받아 위 웹 경로까지 반영했다. PDF 조판·제출·공개 배포는 별도다.

### 이력서 UI 비교

- 로컬 route: `/resume/compare`. 프런트엔드 개발 서버에서만 제공하고 production에서는 404, 검색엔진에는 noindex다.
- [구현](../../../../../app/fe/app/resume/compare/page.tsx)은 [이력서 원문](resume.md)을 직접 읽어 하나의 문서 구조를 두 스타일로 렌더한다. 원문 사본이나 별도 성과 목록을 만들지 않는다.
- 기존안: 공용 UI의 이름·역할 헤더, 연락처 칩, 성과 번호, 경력 메타데이터 열과 여백을 유지한다. 좁은 비교 지면에서는 헤더의 경력·연락처를 두 줄로 배치한다.
- 고전안: 중앙 정렬 인적 사항과 연락처, 단일 읽기 컬럼, 간결한 구분선과 작은 제목을 사용한다. 특정 기관의 공식 템플릿이나 ATS 통과 보장을 의미하지 않는다.
- PC에서는 나란히 보기·단일 양식 보기, 모바일에서는 단일 양식 전환을 제공한다. 같은 항목 선택으로 문서의 대응 섹션을 찾을 수 있다.
- `node --experimental-strip-types --test app/fe/app/resume/compare/source.test.mjs`가 원문·순서·claim을 검증한다. `make verify`에도 게이트 30으로 연결했다.
- `node app/fe/app/resume/compare/browser-check.mjs <Orca-page-id>`가 PC 1920×1080·1440×900와 모바일 390×844에서 실제 전환·스크롤·문구 동등성을 검사하고 `output/harness/resume-ui-comparison/`에 결과와 PNG를 생성한다.
- 2026-09-08 검증: 원문 회귀 검사 3건, 실제 브라우저 9개 상태(문구 58개·claim 59개 동등, 가로 넘침 없음), scoped ESLint·TypeScript·production build·`make verify` PASS. PC 첫 화면·경력·기술과 모바일 첫 화면·자격 영역 PNG를 직접 검수했다. 로컬 비교 route 200, production 비교 route 404를 각각 확인했다. 다른 active route 13개도 200이다. PDF 생성·조판 검수는 이번 범위가 아니다.
- 남은 결정은 **이력서 양식 최종 선택과 공용 4종 화면 검토**다. 비교 화면은 같은 원문을 유지하며, 현재 공용 이력서는 고전안을 우선 적용했다.

| 성과축 | 승인 후 시각화할 관계 |
| --- | --- |
| 크리에이터의 새로운 채널 운영을 제품으로 | 고객의 시작 장벽→제품 흐름, 생성·승인 상태와 발행 실패 분기, 원장→Outbox→수신 버전 판정 |
| 업무 정책을 실행 가능한 백엔드로 | 사용자·서비스·기기 세션과 로그아웃 대상, 주문·알림 책임 분리, 발화 순번과 늦은 보정 |
| 팀이 같은 기준으로 제품을 만드는 기반 | 기능 구현자와 공통 계층의 책임, 트랜잭션 전파·task 소유권·취소 시 정리 |

서버 배치·네트워크 구조가 필요한 경우에만 서버 아키텍처 스킬을 적용한다. 상태표·시퀀스까지 서버 아이콘으로 강제하지 않는다. 기존 도식도 이번에 정정한 BAY·현재 검색 구조와 사실이 맞는지 확인한 뒤 재사용한다.

## 아직 합치지 않은 항목

- 고객 성장 사례의 기간·시작/종료 팔로워 수·실제 사용 기능·다른 성장 요인은 미확인이다. 사용자 확인 범위의 한 사례는 그대로 사용하고 신규 기능의 직접 성과로 연결하지 않는다.
- 최근 생성·승인 기능의 실제 고객 사용 범위·시간 절감 수치는 미확인이다. 새로운 수치 없이 구현·로컬 검증 범위로 설명했다.
- 레거시 이관의 최신 스크립트 전체 작성자와 전면 전환 완료는 미확인이다. 기존의 운영·예약 백엔드 기여는 유지하고 신규 이관 성과는 보류했다.
- 학력·대표 특허·제품 수상·자격은 반영했다. 추가 교육 과정·학내 및 해커톤 수상은 별도 stable claim이 준비되지 않아 이번 CV에 새로 승격하지 않았다.
- 공용 웹 4종은 로컬 반영했다. 포트폴리오의 기존 별도 상세 경로·회사별 제출본·frozen 패키지·채용 플랫폼은 교체하지 않았다. PDF와 배포는 후속 결정이다.

이번 변경에는 커밋·push·배포·제출이 포함되지 않는다.

AskLauncher가 right:24 · bottom:24를 이미 점유(root-phase2·resume 실측). Toast는 상단 중앙에 topbar 바로 아래로 스택.

결정 · 단색 반투명 D2 · MODAL BACKDROP

dim 처리

모노크롬 dim은 rgba(17,17,17,.55) 단색 반투명. topbar의 blur(8px)와는 역할을 분리.

이유: topbar blur는 스크롤 콘텐츠를 비추는 유리(sticky nav) 용도지만, Modal backdrop은 배경을 가리는 게 목적. blur를 쓰면 잉크 모노크롬의 검정↔흰 대비가 흐려져 초점이 약해짐. --fg(#111) 기반 단색이 radius-0 하드 시스템과 더 정합. 택: 단색 반투명 / 반: blur
결정 · 풀스크린 D3 · MOBILENAV 패턴

720px 이하 구멍

topnav가 display:none되는 실제 구멍(index 실측). 라우트 4~5개 → 풀스크린 오버레이(검정 반전).

이유: drawer는 부분 화면이라 4~5개 라우트에 과하고 여백만 낭비. 인라인 확장은 sticky topbar의 blur 유리와 z-레이어가 충돌. 풀스크린 오버레이가 최소 구조이면서 mono의 잉크 반전(검정 배경·흰 글자) 규율을 그대로 재사용. 택: 풀스크린 / 반: drawer·인라인 확장
결정 · 9차 type scale 반영 D4 · TYPE SCALE base 16

본문 앵커 14→16

9차 확정 계약(root-v3 기준)으로 :root 동기화. 본문 계열 base 14→16 · sm 12→13 · lg 16→18 · xl 20→22, xs 11→12, --leading-body 1.45→1.55. 하드코딩 10px 라벨 15곳을 --text-xs(12px 하한)로 흡수.

이유: 타이포만 바꿈 — 색·간격·컴포넌트 문법·데모 문구·Decision 3건은 불변. 하한 12px·10px 전면 금지(8차 확정)를 시트 미세 라벨(specimen hint·state caption·배지류·code 조각)에도 일괄 적용해 계약과 정합. 근거: 9차 D5(업계 실측 · 개발자 문서 전원 16 · 토스 17·카카오 16) · 새 토큰 0

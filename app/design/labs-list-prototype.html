coming-soon 데모 카드 vs 안내 배너 vs 완전 빈 화면 + 한 줄

두 페이지 공통 문법으로 “정직한 데모 1건 + 하단 notice 배너”를 결정. 목록 영역엔 실제 계획에 있는 소재(labs=jarvis, blog=구조 예시 행) 하나를 status 배지(BUILDING/준비 중)를 단 채 보여 “이런 모양이 된다”를 전하고, 그 아래 배너로 “현재 0건”을 못박습니다.

완전 빈 화면 + 한 줄을 택하지 않은 이유: labs·blog는 둘 다 관문(설명이 먼저 오는 페이지)이라 화면이 비면 “아직 아무 계획도 없다”처럼 읽혀 관문의 존재 이유가 약해집니다. 반대로 데모를 가짜 완성품으로 두면 정직성이 깨지므로, 배지+배너로 미완임을 이중 고지해 균형을 잡았습니다.

배너만 두지 않은 이유: 배너 한 줄은 “무엇이 준비 중인지”의 형태를 못 보여줍니다. 데모 카드가 카드 레이아웃·메타 구조를 미리 확정해 두면, 실제 entry가 등록될 때 목록이 곧바로 채워집니다.

택: 데모 카드 + notice 배너(공통) / 반: 배너 단독 · 완전 빈 화면
결정 · labs 카드형 DECISION 2 · 목록 문법의 통일

portfolio 넘버드 리스트에 맞출지 vs labs·blog 각자 자연형으로 갈지

상위 문법은 공유하되, 목록 형태는 페이지 성격에 맞게 분리로 결정. labs는 카드형, blog는 행형, portfolio는 넘버드 리스트 — 셋 다 좌측 mono 인덱스 · 1px 하드보더 · status 배지라는 공통 규율을 공유해 “같은 문서 계열”로 읽힙니다.

labs를 카드형으로 둔 이유: labs entry는 kind(feature/service) × status라는 2차원 메타가 핵심입니다. 카드는 이 두 축을 상단(kind·status 배지)과 하단(진입 목적지)으로 나눠 담기 좋습니다. 이를 한 줄짜리 넘버드 리스트에 욱여넣으면 배지가 이름과 충돌해 답답해집니다.

portfolio에 강제로 맞추지 않은 이유: portfolio 리스트는 순번=읽는 순서인 세로 스캔이 일이지만, labs는 순번보다 종류(내장 기능인가, 독립 서비스인가)가 먼저 궁금합니다. 형태를 억지로 통일하면 각 페이지가 답해야 할 질문이 흐려집니다.

택: labs=카드형(kind·status 2축) / 반: 넘버드 리스트 강제 통일
